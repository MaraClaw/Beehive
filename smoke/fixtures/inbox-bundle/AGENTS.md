# INBOX BUNDLE FIXTURE KNOWLEDGE BASE

## OVERVIEW

This bundle verifies inbox import preserves local attachments linked from both Markdown and HTML clips.

## STRUCTURE

```
clip.md          # markdown clip references ./assets/graph.svg
clip.html        # html clip references ./assets/graph.svg
assets/graph.svg # linked local asset, intentionally simple
```

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Markdown link | `clip.md` | Relative asset reference must remain valid. |
| HTML link | `clip.html` | Same preservation contract through HTML ingest. |
| Asset | `assets/graph.svg` | Fixture exists because both clips reference it. |
| Assertions | `../../../packages/engine/test/tiny-validation.test.ts`, `../../../scripts/live-smoke.mjs` | Update when bundle semantics change. |

## CONVENTIONS

- Preserve relative `./assets/graph.svg` links in both clip files.
- Keep the SVG tiny; visual fidelity is not the purpose.
- Bundle-level semantics matter more than individual asset contents.
- Canonical copied outputs are generated by ingest; source fixture remains here.

## ANTI-PATTERNS

- Do not move the asset without updating both clips and tests.
- Do not inline or remove the asset link; attachment preservation is the fixture purpose.
- Do not add child instructions under `assets/`; it is data-only.

## NOTES

- This fixture is separate from the tiny matrix because inbox bundle preservation is a different source path.
